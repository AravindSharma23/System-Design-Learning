System design is mainly divided into High-Level Design (HLD) and Low-Level Design (LLD). HLD explains the overall architecture and scalability, while LLD explains the internal code structure and object interactions.

B. SOLID Principles
S: Single Responsibility Principle

A class should have only one primary responsibility.

Plain Text
1
Bad:

4

O: Open/Closed Principle

A class should be open for extension but closed for modification.

L: Liskov Substitution Principle

A child class should be usable wherever its parent class is expected without breaking behavior.

I: Interface Segregation Principle

Avoid forcing a class to implement methods it does not need.

D: Dependency Inversion Principle

High-level modules should depend on abstractions, not concrete implementations.

4. HLD vs LLD
Area	HLD	LLDFocus	Overall system architecture	Internal component design
Main question	How will the entire system work?	How will the code be structured?
Scope	Services and infrastructure	Classes and methods
Includes	APIs, databases, queues, cache	Classes, interfaces, patterns
Diagrams	Architecture and data-flow diagrams	Class and sequence diagrams
Scaling	Major concern	Limited focus
Technology choices	Usually included	Implementation-oriented
Audience	Architects and senior engineers	Developers
Example	Chat service uses WebSocket and Redis	MessageService.sendMessage()
